# 2026-10-25：一加后台手环确认与距离复查

## 真实操作结果

保留数据将一加由0.3.2更新至0.4.0，仅更新一次；原 VM 实验公钥保持一致，手环与运动健康的配对未改动。用户启动原 VM 中继，电脑使用10月23日准备的新版 BLE 助手，USB 无授权数据映射。

显式开启30分钟后台手环确认，手机返回主屏幕并熄屏，前台服务仍在运行。两轮由用户手动锁 VM、在手环操作：

| 操作 | 手机记录 | 用户观察 |
|---|---|---|
| 手环点击一键解锁 | 授权响应1次 | VM 自动返回桌面，未输入密码或切换登录方式 |
| 新一轮先等8秒，再点拒绝 | 拒绝响应1次 | VM 全程保持锁屏 |

导出的后台报告记录39次轮询响应、2次通知尝试、1次授权响应和1次拒绝响应。Windows 报告确认本轮 **Indication**、MTU517、40条完成流；手机流计数含开始／中断，不能直接要求与完成数相等。Windows 记录过一次 `target-read / SocketException / 10053`，发生在约86.5秒，随后自动重连，最终共2次连接尝试。此错误仍存在；功能通过不等于长期无故障。

这次使用原来的 VM 中继，未采集新 WTS 自动报告。桌面结果来自用户，手机交付计数和 Windows 传输计数为工具记录；不将传输完成当作独立的 Windows 认证证据。测试结束后停止 BandKey 手机服务和电脑助手，未注册或更换任何登录组件。

## 手环距离：尚无可用信号

用户明确选择**以手环判断距离**，不使用手机 RSSI 代替。Windows 两次30秒扫描均正常完成，无扫描错误：一次普通状态，一次用户将手环放到电脑旁约1米并点亮屏幕。两次都没有发现已知目标地址，第二次也没有 Huawei／Band11／Candy／CDY 名称候选。只说明本轮未观察到，不证明手环永远不广播；随机地址或不带名称的广播仍不能被安全归属。

当前 Wear Engine 5.0.3.304 的公开 `DeviceClient`、`Device`、`MonitorClient`、`MonitorItem` 接口已核对。状态包括与运动健康连接、佩戴、电量、充电等；没有发现读取 RSSI、修改发射功率、启动额外 BLE 广播或广播自定义标识的公开方法。[华为业务简介](https://developer.huawei.com/consumer/cn/doc/connectivity-guides/service-introduction-0000000000018585)说明穿戴设备通过蓝牙私有协议与手机交互；[MonitorItem 文档](https://developer.huawei.com/consumer/cn/doc/connectivity-References/monitoritem-0000001059433013)的连接状态也不是电脑到手环的距离。

因此目前不能把“Wear Engine 服务已开通”解释成“可让手环额外广播”。手机与手环连接正常、通知能到达或佩戴状态为真，都不能说明手环在电脑旁。未调用不公开命令、传感器、重新配对或修改固件。手机诊断页面的地址输入被输入法转成全角冒号，本轮取消了该扫描，不把它记录为有效手机广播结果。

当前真实可用的是手环确认 VM 解锁。**电脑检测到手环靠近后自动触发请求、手环走远后自动锁屏，仍未实机实现。**要继续该目标需要找到这款固件支持的可持续广播／连接测距接口，或明确支持的设备侧开发通道，不能用模拟信号或手机信号补成成功。

原始报告、UI与广播记录均在忽略的 `artifacts/validation-20261025/`，不进入Git。

## 后续场景确认与实测补充

用户随后确认需要两种模式：手机固定在电脑旁时观察手环连接；手机随身时允许以手机与电脑的BLE信号判断范围。两种模式均在手环点一次确认后才请求Windows认证。该选择不改变前述“手环自身广播未找到”的事实。

固定手机的只戴手环走远／返回实测已捕捉到连接→断开→重连，详见[两种模式](proximity-modes.md)。因此固定手机方案不依赖电脑发现手环广播。手机状态签名上报、实际自动锁屏和长时间锁屏后的新请求仍待整合，不能把状态观测当作完整解锁联调。
