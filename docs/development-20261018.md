已实现并测试：

- Core 中的 `IDeviceObservationSource`、`DeviceObservation` 统一描述观测结果，包含传输来源、地址及类型、RSSI、时间戳、广播类型、连接/扫描标志和有界数据段。

## 一次性签名与加密保管阶段

用户随后反馈前轮手动密码实验全部正常，按该轮反馈范围记录为：VM 安装、正确密码实际进入桌面、错误密码被拒绝、原有系统登录保留、卸载通过。它属于用户报告，未由工具独立观测；快照恢复仍未验证。用户继续负责所有虚拟机操作。

在既有 V2 Provider 上新增模式 2，未重建工程。安装器由用户手动登记独立 VM 密码，先以 Windows LogonUser 校验账户 SID，再使用机器 DPAPI 加密并置于 SYSTEM/管理员专属 Vault；解密时再次检查文件所有者/ACL及非重解析点。机器 DPAPI 本身不阻止同机用户解密可读取的密文，因此不以 DPAPI 替代文件权限。管理员及系统被控制不在保护范围内。

Provider 自己在内存持有 30 秒挑战，绑定 SID、Windows 会话和随机 nonce，独立核验 P-256 签名、时间、锁屏状态及当前配置，再原子消费后读取密码、通过 CredProtect/Negotiate 交给 LogonUI。授权、序列化和桌面实际解锁分别判定。通知回调使用原 COM apartment 的消息窗口和定时器，避免跨线程调用事件接口；其真实 LogonUI 生命周期仍需来宾验证。

新增 VM-only 确认客户端，使用当前 VM 用户 DPAPI 保护的模拟私钥。默认 Disarmed，由用户点击后只允许 30 秒内的一个新请求，可生成有效或故意错误的签名。它不接收 Windows 密码、不自行锁屏，也不代表真实手环点击。当前 Android v1 授权格式不能自动转换为原生授权；未来设备必须明确签署新正文并接入真实来源策略。正式 C# 后端仍为 UnavailableAuthenticationBackend。
