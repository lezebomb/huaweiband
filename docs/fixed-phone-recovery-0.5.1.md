# 固定手机刷新循环修复：0.5.1

0.5.0实测未通过：返回后通知延迟，点击未解锁；直接重新锁屏也未稳定产生通知。手机记录72次状态、13次刷新，仅1次通知、0次批准交付；VM截图累计138次状态、33次刷新，原生日志确认反复生成挑战。不能把刷新当作解锁成功。

修正一处会导致该现象的状态机路径：短暂未知、心跳空档或尚未达到远离时间的抖动，不再重置本轮请求并取消当前原生挑战。它们仍关闭提交门禁；恢复有效、稳定的接近证据后，仅能继续本来尚未过期的同一挑战。持续远离、会话变化、显式重试或撤销仍产生新轮次。

手机只在收到新的刷新响应时取消旧通知票据，数据短暂不可用时暂停提交。固定模式轮询／决定IO限制为3秒，避免原15秒等待阻塞8秒状态窗口。30秒授权、10秒刷新、签名及一次性检查没有延长或绕过。

报告新增SDK查询耗时、连接／断开／未知计数及原生等待原因，不含设备标识、密钥或健康数据。四项针对性回归通过；仍需当前VM实际验证，不能称为已解决全部硬件问题。

## 只替换中继，不重装登录组件

VM由用户操作，手机由开发端处理。保留旧目录以便回退。

1. 用原系统密码回VM桌面，停止中继并退出旧窗口。
2. VMware光驱选择本轮 BandKey-Relay-Update-*.iso。它不含VmSetup，不运行登录安装器。
3. 将光盘 VmBridge 整个目录复制到VM新文件夹，例如 C:\BandKeyFixedPhone051\VmBridge。双击 Start-VM-Bridge.cmd。
4. 导入光盘 Phone-VM-public.bandkeypub，核对原一加公钥。本机监听填VM实际IPv4（此前192.168.71.130），手机地址保持 https://127.0.0.1:19443。
5. 勾选固定手机模式，自动锁屏保持关闭，再启动中继。原Windows用户和电脑身份未变时，手机不重新配对。
6. 手机保留数据更新一次到0.5.1，重新开启固定模式后台手环确认；开发端会处理。不要同时开启旧后台BLE或页面轮询。

第一轮不用走远：只锁VM，新通知出现后立即手环确认，观察Windows是否真正回桌面。通过后才测超过40秒的离开／返回，再测拒绝保持锁屏。没有新通知时读取中继末行等待原因，避免反复猜测。

## 回滚

停止新中继和手机服务，启动保留的旧中继目录。手机关闭固定模式可继续原手环手动VM联调。此次没有修改原生登录组件或宿主机登录。已经交付的签名无法撤回，原生期限和一次性检查仍适用。
