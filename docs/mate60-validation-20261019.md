## 本轮发现和修复

初版 APK 在 Mate60 上已完成 USB 和一次 BLE 流程，但第二次 BLE 复验出现电脑发出 3827 字节、手机统计 3670 字节的差异。该轮明确记录为失败。原因是电脑统计 GATT 接收确认，手机统计写入 TLS Socket 的数据；最后错误证书反例会关闭 Socket，两个层级不能直接比较。

现在两端都在 GATT 接受帧时统计有效载荷。手机的帧接收与会话结束使用同一锁，测试在最终反例后等待流退出，再读取统计。上述当前 APK 的新一轮实机检查已得到完全相同的双向计数；没有放宽为“有数据就算通过”。

错误证书测试现在必须找到异常链中明确的证书指纹不匹配原因。普通 SSL 断开、过期证书和相同文本的普通 IO 错误不能充当证书拒绝证据。独立 JVM 分类测试 5/5 通过，当前 USB / BLE 也实际通过此更严格判定。

共享报告验证器检查本轮 ID、11 个唯一检查名、两端字节/流数、唯一交付、无 USB 数据映射、CNG 和合成账户边界。14 项报告回放/变异测试通过，覆盖陈旧结果、计数不一致、重复检查、重复交付、缺失边界标志及未知主机错误等；这些属于软件测试，不计入新的实机轮数。发布清单和 VM 数据镜像复用此验证器，并要求主 APK 哈希一致。

最后的错误证书连接允许出现预期的传输取消，但只有其他检查全部通过且双向计数一致才接受；报告分别记录正常停止和预期反例终止。当前修正版实机轮次为正常停止。

安装过程中曾有一次用户拒绝和一次等待确认超时，均未算作通过；锁屏的安全键盘无法由工具可靠恢复，用户手动解锁后继续。没有移除或修改手机锁屏密码，没有更新系统安装器。原普通桥接密钥保持不变，实验密钥使用独立别名。

## 连续测试与安装复用

USB 和 BLE 脚本均先读取已安装 APK 的 SHA-256，与本地文件一致时跳过安装。按用户要求，连续测试默认保留测试 APK，避免 USB/BLE 切换时反复触发安装器。只有显式传入 `-RemoveTestPackage` 才清理 `dev.bandkey.bridge.test`；主应用及其密钥始终保留。本轮最终实测是在此策略调整之前执行，临时测试 APK 已被旧清理策略移除，未为重复同一轮测试再次安装。

后续只读验证分别调用两个脚本中的实际安装检查函数，并在验证器中禁止安装命令；两者均成功复用手机现有主 APK。主应用已直接启动，测试数据映射为空。

```powershell
./scripts/test-phone-usb.ps1 -AdbPath '<platform-tools目录>\adb.exe'
./scripts/test-phone-ble.ps1 -AdbPath '<platform-tools目录>\adb.exe' -GrantNearbyPermissions
./scripts/test-ble-evidence.ps1 -SourceReport '<本轮BLE目录>\summary.json'
```

有多个授权设备时显式传入 `-Serial`。脚本只授予本应用的蓝牙 CONNECT / ADVERTISE 权限，不为其他应用授权。安装新版本仍可能需要手机本人的安装确认；不尝试绕过安全锁屏。

## 后续实际 VM 本地账户联调

2026-10-19 复用上面的同一主 APK，未重新安装。用户在 build 26300 的 BandKey-Win11 中登记手机确认模式，输入独立 VM 账户密码并运行中继。工具核对手机公钥、电脑公钥哈希及 VM TLS 指纹，向手机导入公开配对资料，未接收或传输 Windows 密码。VM 由用户手动操作，宿主机登录配置、Ubuntu 和手环配对保持原状。

| 轮次 | 工具实际观察 | 用户实际观察 | 判定范围 |
|---|---|---|---|
| USB 有效确认 | 新请求、仅点一次确认、手机显示签名已交给原生组件 | 自动返回桌面，未输入密码或切换其他登录方式 | 实际手机 → VM 本地账户正例获用户确认 |
| USB 不确认后拒绝 | 8 秒不批准，再点一次拒绝，返回 `user-denied` | 全程保持锁屏 | 本轮未确认／拒绝及旧授权未沿用获用户确认 |
| BLE 有效确认 | 真实 GATT 就绪、无 ADB 数据映射、一次确认、手机显示交付 | 自动返回桌面，未输入密码或切换其他登录方式 | 实际 BLE → VM 本地账户正例获用户确认 |
| BLE 不确认后拒绝 | 8 秒不批准，再点一次拒绝，返回 `user-denied` | 全程保持锁屏 | BLE 本轮未确认／拒绝及旧授权未沿用获用户确认 |

手机按钮由开发工具按用户授权代点，签名来自实际 Keystore；没有真实手环按钮事件。没有独立采集来宾 Windows-result / WTS，也没有读回已安装来宾二进制哈希，因此桌面结果明确属于用户报告。每路只有上述正、反例，不能当作原生 30 秒挑战过期、完整重放攻击、长期后台或全部认证边界的验收。VM 实验仍以加密保管的本地账户凭据进行系统认证，不等于 Windows 无密码登录。

BLE 授权数据未经过 USB 或同一 Wi-Fi；USB 线仍用于 ADB 控制，没有拔线运行验收。USB 助手结束后移除本轮映射，报告接入 347、拒绝 0、失败 0。BLE 助手记录 MTU 517、完成流 56、发送 33742／接收 70293 字节，但在最后拒绝后、人工停止前以 `stream-failed / IOException` 退出。该错误根因未确定，持续连接稳定性记为未通过；上述主机单侧统计也不是本轮两端计数一致的证据。最后停止手机轮询和 BLE 服务，确认 ADB 反向映射为空，保留应用与配对。没有宣称中继组件自己提交 Windows 认证；实际桌面结果来自用户观察。

较早还有两项失败单独保留：VM 曾端口不可达／截图黑屏，原因未确认；首次较慢的手机确认没有观察到交付且用户仍在锁屏，原因未确认。随后在新锁屏周期及时确认成功，期间未更改 APK，不能把它称为已通过代码修复解决。

本地忽略目录中保存 `artifacts/vm-live-phone-positive-1.json`、`vm-live-phone-negative-usb.json`、`vm-live-phone-positive-ble.json`、`vm-live-phone-negative-ble.json` 及传输报告。历史 ISO 和发布清单保留打包时的 `guestTested=false` 状态，后续用户证据单独记录，不回写旧产物。复现步骤见 [VM 手机教程](vm-phone-bridge-test.md)。
