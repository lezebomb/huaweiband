随后定点通信中断测试未取得新通知，原生请求过期；当时手机退桌面为脚本Home操作，后台服务实际仍在。次日另查到系统夜间清理过进程，两者有区别。0.9.2已加入传输重建、本地流关闭处理和受主动停止限制的系统恢复任务；桌面BLE／HTTPS恢复已实测，随后锁屏中的受控中断、新通知及真实手环确认解锁也已通过。实际携带返回与整夜常驻仍待验证。见[修复证据](ble-resident-recovery-0.9.2.md)、[完整认证记录](host-return-unlock-20261028.md)。

手机与手环可一起携带：主机新增“已认证手机通信恢复”提示。在至少15秒没有收到有效状态后，新的有效签名状态恢复、且所选手环仍连接，重新接近稳定后可创建新的原生登录请求。手机不需要先与手环断开，也不需要同一Wi-Fi。通信恢复只是发通知的条件，不能批准解锁；旧通知／旧签名不继承到新请求。

此流程依据通信可达性，不是几米范围或RSSI：若手机与电脑一直未失联，不能认定发生新的返回。长时间网络故障恢复也可能产生新提示，仍必须手环本次确认。尚未将手机随身RSSI后端宣称为已接入。软件检查181项核心、101项Windows通过；实际携带手机离开／返回尚待验证。

此包从已验证的 VM 原生认证链路派生，主机使用独立的 GUID、登记、文件夹和锁；VM 限制保持原样。主机二进制只接受构建时的电脑与 Windows build、当前微软账户、已登记手机公钥和一次性签名。原系统密码与 Hello 提供程序保留，不设置自动登录、不使用模拟键盘。

- 真实主机第二轮批准成功：原生日志依次出现 `approval-verified`、`grant-consumed`、`serialization-prepared`、`Windows-result=0`，用户确认未输入密码自动返回桌面。
- 第一轮手环点击有效，但手机提交发生 SocketException，Windows 未收到签名；另一轮拒绝测试未收到通知。这些失败保留记录。修复后新一轮已记录 `user-denied`，用户确认等待8秒及拒绝后主机始终锁屏，未沿用上一轮授权。
- 默认 TLS 协商观察到 TLS 1.3；TLS 1.2 比较仍出现 TCP10053，已恢复默认协商，不能将故障归因于 TLS 版本。兼容开关默认关闭，不放宽证书校验。
- 主机数据流修复只处理电脑 TCP 的10053／10054：将该流结束传递给手机，必须收到同一会话、严格序号的 EOF 后才读下一个 OPEN。截断的 TLS／HTTP 仍由端点拒绝；不会重发解锁决定。中断流单独计数，不算成功流、不补充重连预算。实机已观察到同一 GATT 内结束2个中断流并继续传输；随后仍有一次 CCCD 丢失且自动重连，不能宣称长期无故障。旧 VM/通用助手默认处理不变。
- 主机走远尚未完成验收。手机后台的66次SDK断连和21份断连报告是整个运行周期的累计数据，不能归因于某一轮；据此推断当轮软件失效的判断已纠正。新中继独立记录的后一轮为31份已连接、0份断连，未满足自动锁屏条件。保持原有防误锁策略，不用累计历史或手机离开替代实际手环断连，也未保留临时尝试的“断连基线记忆”策略。

## 一次安装

1. 运行包内 `Native/BandKey.HostSetup.exe`，选择 Install，批准管理员提示，选择当前手机的 `.bandkeypub` 公钥。
2. 在本机 Windows 凭据窗口输入实际账户密码，不能使用 Hello PIN，也不要向聊天发送密码。安装器核对 SID 后，用机器 DPAPI 和 SYSTEM/管理员 ACL 保护密文。
3. 运行 `install-host-agent.ps1`。它核对包文件哈希、当前用户登记，复制到当前用户的 Programs/BandKeyHostPilot，建立仅在此用户交互会话运行的登录任务，启动后台托盘。异常退出由任务计划程序重新启动，正常“退出”保留到下次登录启动。
4. 手机保留数据更新后，导入电脑生成的公开 `public-pairing.json`，核对电脑 ID、公钥与证书指纹。启用真实手环、固定手机模式，再启用常驻手环确认一次，并允许 BandKey 自启动、后台活动和不受电池优化限制。

之后无需每次打开中继、BLE 传输或手环程序。关掉电脑窗口进入托盘；手机 Home、熄屏、移除最近任务不停止主机常驻模式。手机开机或应用更新后恢复已启用的常驻配置。系统“强行停止”应用、撤销权限或厂商后台限制仍可能需要重新打开应用。

本阶段电脑桥接在用户登录后运行；电脑冷启动首次登录仍用 Windows 原来的密码／Hello。自动恢复不等于自动批准：每次解锁仍需手环明确确认有效的新请求。

## 距离与验证边界

固定手机模式要求手机留在电脑旁，通过 Wear Engine 的手环连接状态判断离开／返回，不提供米数。初次主机试用默认关闭离开自动锁屏，先验证真实手环批准、等待与拒绝仍锁屏，再启用自动锁屏。

离开自动锁屏当前已按用户要求关闭。若以后重新启用，主机持续断连等待为 **5秒**，从新鲜、已签名的断连状态开始计时；接近稳定等待仍为1秒。VM实验的15秒默认值保留。

恢复速度受华为运动健康重新连接手环的时间影响。本版仅将已断连时的本地 SDK 查询缩短为 1 秒，保留已验证的 3 秒网络状态节奏；实际返回延迟需实测，不能承诺重连前即通知。

## 暂停与恢复

托盘右键“暂停”撤销当前请求并停止传输，暂停配置跨登录保留；“恢复”重新连接。手机通知栏可停止，停止后不会在下次开机恢复。旧通知、超时签名或上一轮确认不能用于新请求。

Windows 功能更新改变 build 后，主机绑定会拒绝 BandKey，原密码／Hello 仍可使用。重新验证并构建相应版本；卸载器可在同一电脑更新 build 后撤销 BandKey。

## 卸载／回滚

开始菜单 BandKey → Uninstall BandKey：先停用自己的登录任务，停止当前用户代理，再调用受保护的本机卸载器撤销 BandKey 的原生登记与凭据密文，删除代理文件。若原生 DLL 正在被 LogonUI 使用，登记已撤销后按提示重启，再运行同一卸载入口完成文件清理。

备用恢复入口：`C:\ProgramData\BandKeyHostPilotRecovery\BandKey.HostSetup.exe` → Remove。此入口不依赖工程目录、手机或桥接运行，也不需要读取密码。仅处理 BandKey 自有登记和文件，保留系统登录方式。

VM 的安装、移除、重启原登录恢复、快照还原后真实手环解锁已经用户实测；主机版本与长期常驻须单独实测，不以 VM 结果代替主机验收。
