# 携带手机模式后端：2026-10-26

2026-10-27补充：物理主机已安装独立试用配置，现新增的是“已认证手机通信恢复后发起新确认”，详见[主机说明](host-resident-pilot.md)。它不要求手环先与手机断开，也不使用RSSI或宣称精确靠近距离。本文下面的RSSI生产者绑定与阈值接入仍未完成，不能把通信恢复通知记作RSSI模式验收。

目标行为是手机和手环一起带走／回来，用手机到电脑的 BLE 信号判断接近，最后仍由手环点击确认。原来的“手机固定在电脑旁，用手环连接状态判断返回”是另一个模式。

## 已实现的软件

- `CarriedPhonePresence` 统一处理当前 GATT 连接代次、具体广播地址及地址类型、已验证手机身份和手环连接状态。RSSI 沿用已有中位数、平滑、时间窗口和滞回算法，不换算米数。
- `BlePhoneTunnel.Peer` 在成功建立连接后暴露本地连接绑定；每个新连接生成新 ID，记录从广播得到的地址类型，断开、传输结束、取消或释放时失效。重连不沿用旧连接代次。创建 Windows BLE 对象时使用带地址类型的[官方 API 重载](https://learn.microsoft.com/en-us/uwp/api/windows.devices.bluetooth.bluetoothledevice.frombluetoothaddressasync)。
- `CarriedPhoneObservationSource` 复用 Windows 被动扫描器，只把当前已绑定设备的有效新样本交给距离模块。名字、服务 UUID 或相同 MAC 本身不能标记为已认证。
- `VerifiedPhoneLink` 是本地认证层的输入契约，包含已验证手机指纹、准确的连接代次、单调时间及手环连接状态。它本身不是签名证明，距离模块不实现重复验签，不能把 HTTP／JSON 中同名字段直接当作可信对象。
- 认证证据超过 10 秒、RSSI 样本过期、用户注销／解锁、地址或代次变化都会关闭或重置确认门控。扫描故障、恢复睡眠后必须使用新连接代次。模块不自行创建登录挑战或撤回已签名消息；跨接近周期的新挑战和旧通知作废仍须由接入它的认证协调器处理。
- 默认不因信号消失锁屏。显式开启缺失信号策略后，已可信地进入 Near 的连接真正消失才按既有缺失窗口判断；扫描器故障或认证失效归为未知，避免把故障直接当作离开。弱信号持续远离的自动锁屏仍受 Session 0 保护，接近本身不会批准登录。

## 接入约束与当前缺口

这是后端模块，尚未开放实机设置入口。现有运行流程没有生产者把签名验证结果与准确的本地 GATT 代次关联为 `VerifiedPhoneLink`，因此不能只填一个手机 ID 或固定布尔值就启用它。后续应由完成验签的通信层提供该对象，连同 `BlePhoneTransport.Peer` 注入采样源，再将 `Presence.CanRequestConfirmation` 接入现有认证门控，并在新的返回周期使用请求刷新协议生成新原生挑战。不能把本阶段的距离模块当作已完成跨周期授权撤销。

当前 VM 中继在来宾内、物理 BLE 通道在宿主机，两者没有可信的跨进程／跨 VM RSSI 输入通道。本阶段没有添加无认证的距离 HTTP 接口，也没有因此开放主机登录安装。正式主机部署仍等待微软账户 LogonUI 与恢复路径验证。

还需用真实手机确认连接后是否仍提供足够新广播、随机地址变化、电脑蓝牙适配器兼容性和阈值效果。如果实际收不到新广播，状态会过期为未知，不能沿用扫描缓存或伪造 RSSI。BLE 信号及签名不能单独证明物理距离或排除无线中继攻击，最后仍须手环本次明确确认。

## 软件验证范围

最终构建为零警告、零错误；核心 168/168、Windows 91/91 通过。本阶段新增 17 个核心及 3 个 Windows 用例，没有重跑与改动无关的原生或 Android 全套测试。原生登录 DLL SHA-256 仍为 `9f60ae7222f0836f9a4739370f4676e2460def592a4fd53924a0e18943b70ced`。

新增核心用例覆盖未认证强信号、错误手机、错误连接代次、邻近设备、地址类型、匿名／重放／未来样本、身份与 RSSI 独立过期、手环未知／断开、重连、手动解锁、扫描故障、单调时钟回退、Session 0、抖动与一次锁屏。

同现有 `WindowsGrantRelay` 做软件联测：Near 只允许取得请求；仍需独立的有效 P-256 决策才写入模拟原生交换。待决请求出现后 RSSI 过期，即使该决策的签名仍有效也不得提交。该测试没有调用 Windows 登录。

Windows 适配器用可注入扫描源验证过滤、故障和释放；BLE 监督器用可注入连接验证存活期间的代次与退出清理。这些均为软件测试，没有再次操作手机或 VM，不构成本模式的实机验收。

## 启用与回滚

本阶段没有安装或开启新的运行模式。后续实机测试应先观察状态、保持自动锁屏关闭，验证真实身份与信号来源后再评估锁屏配置。模式停止时释放 `CarriedPhoneObservationSource`，恢复时创建新连接，不能复用旧实例的就绪状态。
