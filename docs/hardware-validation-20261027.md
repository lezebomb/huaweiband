# 2026-10-27：0.9 中继与 BLE 恢复实测

组合：一加 PLR110 原版手机 0.8.0、真实 Band 11 Pro、用户手动更新的 VM 0.9 中继，以及主机 0.9.1 BLE 助手。手机没有重新安装，手环配对和原生登录组件没有更改。VM 内操作由用户完成；主机只运行用户态传输，没有注册登录组件。

VM 的实际 TLS 证书与此前导入的公开配对指纹匹配。USB 保留用于调试，没有 BandKey 19443 端口的 USB 转发；授权数据经过 BLE，电脑端不终止 TLS。

## 用户实际观察

| 场景 | 结果 |
|---|---|
| 新锁屏，真实手环确认 | VM 自动回桌面，未输入密码或切换登录方式 |
| 用户估计的通知／确认后解锁时间 | 分别约 3 秒／3 秒；不是同步时钟测量 |
| 新请求先等 8 秒，再点拒绝 | 等待及拒绝后始终保持锁屏 |
| 手机 BandKey 进程主动重启两次，等待 BLE 恢复后再锁屏确认 | 仍自动回桌面，未输入密码 |

桌面与拒绝后的锁屏结果来自用户观察。本轮没有独立采集 Windows ReportResult 或该轮 WTS 归因，也没有重新读取账户类型；沿用之前已登记的 VM 用户，不能把结果写成主机账户验收。

## 软件与传输证据

第一份手机报告：2 次提示、1 次批准响应、1 次拒绝响应；96 次有效固定手机状态、154 次 SDK 查询全部连接成功、错误 0；HTTP 100 次请求、100 次完成。NEW 刷新响应为 0，附带 WIN 挑战为 2，与新锁屏直接提供有效 WIN 的路径一致。决定调用最近值 2076 毫秒对应报告末次决定，不能当作第一次批准的精确耗时。

两次主动重启后另存的报告：1 次新提示、1 次批准响应，NEW 刷新响应仍为 0；SDK 61 次全部连接成功、错误 0，51 次状态上报；该次批准调用 1255 毫秒。导出时 HTTP 55 次请求、54 次完成，服务仍在运行，不能仅用差值认定一次失败。重启前后的报告分开保存，不能将每个新手机服务的计数视为整个 Windows 连接历史。

Windows 助手最终记录 4 次连接尝试、23 条完成流、MTU 517、Indication，发往手机 94918 字节、来自手机 244898 字节。记录保留 3 次故障：`stream-timeout`、`target-read / SocketException / 10053`、`gatt-write-timeout`。本轮主动重启两次，额外的 TCP 中止不能也算作计划内断连。助手后来恢复，并在用户最后确认成功后按停止文件正常退出；`passed=true` 不代表全程没有错误。

累计故障 3、连续故障 3、恢复额度重置 0。本轮说明实际连接可以自动恢复，但**没有验证成功流跨 60 秒后刷新预算的硬件条件**：中间额外中止使连接代次再次改变，手机累计完成流不能替代当前 Windows GATT 代次的成功跨度。原软件注入检查仍是 97/97；不降低实机门槛来制造通过结果。

测试后已停止专用 Windows 助手及手机 BandKey 测试服务；VM 原中继与系统登录登记保留。原始 JSON、UI 记录、配对信息均留在本机忽略的 artifacts/hardware-20261027/，不进入 Git。

## 误导入旧公钥的处理

用户首次启动误选了旧手机公钥，中继按原校验拒绝启动。关闭后重新运行并使用自动读取的当前 VM 登记公钥，即恢复正常，没有重装。

源码随后增加导入保护：已能读取当前账户有效登记时，误导入另一份公钥会保留登记公钥；无效文件也不清空原来已读取的公钥。错误提示改为先检查自动读取和 VM 登录账户，避免引导重复安装。该小改动仅完成 Release 编译（0 警告／错误），未替换本轮测试中的运行文件，也未要求用户再次更新 VM。
