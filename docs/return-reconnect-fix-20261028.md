## 真实失败记录

2026-10-28手机0.9.3和配套主机代理更新后，用户反馈“直接锁屏有通知，走远再回来没有新的通知”。本轮主机于12:26:55锁定，12:27:26签名状态失去新鲜性；结束观察前未恢复。只有初始1次提示，决定和授权文件交付均为0；原生挑战过期，没有BandKey的Windows认证成功记录。随后桌面恢复不能算BandKey解锁成功。

主机同时记录`phone-write / ObjectDisposedException`，该故障未进入原有可恢复错误分类。它证明本轮存在关闭对象写入及重连处理缺口，不能凭此断言是唯一根因。完整新通知和5秒目标均未通过。用户随后需要使用手机，当前阶段不再读取、重启或操作手机，也不要求配合测试。

## 已实现的电脑端修复

- 为当前连接代次明确保留GATT服务和Session；重连发现期间不提前释放其他已枚举服务包装对象，不读取它们的特征。代次结束后统一释放。
- 持有Session引用并监听`SessionStatusChanged`；关闭时清除当前连接证据、取消当前流，再从新的连接代次开始。已经关闭的Session不发布为就绪。
- 生产GATT写入遇到`ObjectDisposedException`时映射为固定的`gatt-session-closed`，按连接故障重新发现；主动取消仍是停止，不启动新写入。不以此重放TLS、请求或已经消费的授权。
- 清理时，一个已经关闭的WinRT对象退订失败不会跳过后续服务／Session／设备释放。保留原有写入期限、限流、帧校验、权限失败规则及原生认证要求。
- 诊断只保存固定错误类别、异常类型和数值，不保存异常文本或对象名称。

服务保留策略是针对生命周期风险的防御修复，尚未证明“提前释放服务”就是这次ObjectDisposedException的具体来源。微软文档确认[每个服务可取得Session](https://learn.microsoft.com/en-us/uwp/api/windows.devices.bluetooth.genericattributeprofile.gattdeviceservice.session?view=winrt-26100)，并提供[Session状态变化事件](https://learn.microsoft.com/en-us/uwp/api/windows.devices.bluetooth.genericattributeprofile.gattsession.sessionstatuschanged?view=winrt-26100)；并未据此推导本机故障根因已被官方确认。
