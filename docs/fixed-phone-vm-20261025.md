# 手机留在电脑旁：手环离开／返回测试版 0.5.0

手机留在电脑旁，通过官方 Wear Engine 查询所选手环连接状态，经原有 BLE 和固定证书的 HTTPS 签名上报给 VM。无需同一 Wi-Fi，不解除配对，不控制手环广播。真实走远／返回已观察到连接→断开→重连；本候选的完整自动锁屏和返回新请求仍待 VM 实测。

这是手机蓝牙连接范围，不是米数。浴室仍在连接范围内时，不会产生离开事件。

## 新增行为

- 显式开启的30分钟后台实验，每3秒查询所选手环。签名报告绑定电脑、手机实验密钥、运行随机上下文、手环哈希、递增序号及采样时间。
- 连接持续3秒视为接近。自动锁屏默认关闭；勾选后，先观察稳定连接，再持续断连15秒，才请求锁定该 VM。
- SDK未知、查询失败、心跳过期或BLE中断不作为走远。短暂抖动不反复锁屏，恢复后重新观察稳定连接。
- VM已锁屏很久时，返回通过独立的10秒“生成新请求”签名触发原生Provider刷新随机挑战。它不批准解锁、不读取Vault。新挑战仍须真实手环当前点击，30秒有效。
- 拒绝／无点击／过期／旧通知不批准。单次返回不无限重发通知；需要重试时点中继“重新请求手环确认”。
- 手机随身的RSSI模式目前只有算法接口，尚未接通。关闭固定模式保留原有VM联调路径。
- 仍仅支持 VMware Windows11 build26300。微软账户实际登录和主机恢复未验收，不在物理主机注册本轮DLL。

## 更新 VM：一次，由用户操作

先用VM原系统登录方式进入桌面，确认密码可用并保存新快照。保留旧ISO、中继目录，不操作Ubuntu。

1. VMware 的CD/DVD选择本轮 BandKey-Fixed-Phone-Lab-*.iso。完整路径见本机 artifacts/latest-fixed-phone-lab.json，不用从光驱删除文件。
2. 停止旧中继并关闭BandKey窗口。运行光驱 BandKey.VmSetup.exe，选 Remove VM experiment。若占用，重启VM再运行Remove直到完成；保留系统登录方式。
3. 再运行同一新安装器，选 Install phone-confirmation VM experiment，选择光盘 Phone-VM-public.bandkeypub（未附时用原已核对的一加实验公钥），核对指纹。只在VM本地对话框输入当前VM账户密码。
4. 复制光盘整个 VmBridge 到VM新文件夹，例如 C:\BandKeyFixedPhone\VmBridge，从新目录双击 Start-VM-Bridge.cmd。
5. 导入同一公钥。本机监听填VM当前IPv4（此前192.168.71.130），手机访问地址保持 https://127.0.0.1:19443。勾选“手机固定在电脑旁”，先不勾自动锁定，再启动中继。
6. 手机保留数据更新到0.5.0，不卸载／清除数据。VM实验页也勾选“手机固定在电脑旁”，启用真实手环并点“启动后台手环确认”。
7. 保持原专用网络防火墙规则。电脑身份保存在该VM用户的 BandKeyVmBridge 目录；未换用户／删数据／换证书时原配对继续可用。指纹变化必须重新核对，不能忽略TLS校验。
8. 宿主机运行本轮 VmBridge/BandKey.exe 的“手机BLE通信实验”，目标填VM实际IP并连接手机。这里只转发到VM。手机可回桌面熄屏，不要同时运行旧BLE助手。

提示“需要协议v3”表示仍是旧登记或旧程序，应回步骤2，不能编辑注册表绕过。

## 最短实测

A. 长时间锁屏后返回：手机留在电脑旁，仅锁VM，等超过40秒；只戴手环走到确实断连处，停约20秒再回来。新请求出现后手环点“一键解锁”，预期VM自动回桌面。先只测这一轮，自动锁屏关闭。

B. 拒绝：再锁VM，完成一次离开／返回，先等8秒再点拒绝，预期始终锁屏。旧通知不能批准新一轮。

C. 离开锁屏：A、B确认后，停中继，勾选持续断连自动锁VM，再启动。手机留在电脑旁，先稳定连接，再戴手环走远，预期持续断连15秒后VM锁定。总延迟还包含系统断连检测、采样和传输；回来仍须手环确认。

记录实际桌面与中继WTS报告；手机签名交付或API返回不能代替锁屏／解锁观察。结束后停止手机服务、中继、电脑BLE助手。

## 回滚

用VM原系统密码登录，停止服务和助手，手机关闭固定模式。VM运行本轮安装器Remove，只移除BandKey实验组件；文件占用时重启再清理。进不去VM则恢复事前快照。

恢复旧实验可用旧ISO重新登记同一公钥并启动旧中继；手机0.5.0关闭固定模式仍可走旧流程，无需清数据或降级APK。不要在物理主机注册本轮DLL。
