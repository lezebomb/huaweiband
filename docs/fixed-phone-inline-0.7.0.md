# 通知快速返回候选：0.7.0

0.6.0实机改善为约10秒通知、2秒解锁；确认排队3毫秒、决定调用1215毫秒，通知等待仍偏长。0.7.0减少刷新后再探测、再单独取挑战的网络往返。

手机在状态／刷新请求中附带原有独立签名PollRequest。中继先验证父请求，再使用原WindowsGrantRelay分别验证手机身份、轮询签名及nonce，只有原生新挑战已就绪且接近状态有效时才将电脑签名的挑战附在同次响应中。刷新响应最多等待400毫秒。手机仍完整验证电脑签名、身份和原生期限；真实手环当前点击才签署解锁批准。

没有合并或跳过任何身份验证，没有延长10秒刷新、30秒授权或30分钟实验期限。旧中继不返回附带挑战时，手机使用原轮询路径回退。原生DLL和账户认证未变。

## 只换中继一次

1. 用原系统登录方式回VM桌面，停止旧中继并退出窗口。
2. VMware光驱选择本轮 BandKey-Relay-Update-*.iso，复制 VmBridge 整个目录到VM新文件夹，例如 C:\BandKeyFast070\VmBridge。
3. 从新目录打开 Start-VM-Bridge.cmd，导入同盘 Phone-VM-public.bandkeypub；监听填VM实际IPv4（此前192.168.71.130），手机地址仍为 https://127.0.0.1:19443。
4. 固定手机模式保持勾选，自动锁屏可保持当前测试选项。启动后状态区应出现“中继已启动（0.7 挑战随响应返回）”，据此确认运行了新版。
5. 手机由开发端保留数据更新一次到0.7.0并接好BLE。先保持VM桌面，之后只原地锁VM一次测速，不重复走远。

光盘没有VmSetup或登录DLL，无需重装、改注册表、换公钥或重新配对。原电脑身份与证书仍在该VM用户原来的BandKeyVmBridge目录。

## 验证范围

核心146、Windows HTTPS集成88、Android生产代码JDK110项通过，Android签名／Lint与Windows发布成功。5项新增HTTP检查验证独立签名、新原生文件等待、伪造父请求不能消费有效轮询nonce、跨手机及轮询重放拒绝；测试使用合成账户，没有调用Windows登录。

当前VM实测确认附带挑战已生效，但用户仍报告约10秒通知、2秒解锁，没有可感知的通知提速；不能把减少请求次数当作体验已经达到目标。

回滚：停止新版中继，运行保留的旧0.5.1目录；手机0.7.0可回退原轮询协议，不必清数据或卸载。物理主机登录组件未改。
