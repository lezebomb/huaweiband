# VM 后台手环确认准备版（2026-10-23）

Android 0.4.0 新增单独开启的 VM 后台手环确认模式，包含本机 BLE 传输、已固定证书的 VM 轮询、真实 Wear Engine 双按钮通知和一次性决定提交。手机可以离开实验页面或锁屏；只有手环本次明确点击才会请求签名。默认关闭，不随开机或进程重建自动恢复。

**实现和软件验证已完成；手机已带走，新版尚未安装。手机后台、锁屏、Wear Engine 实际回调和新版 BLE 交付尚未实机验证，不据此启用主机登录组件。**

## 生命周期与授权范围

- 必须从已解锁的应用前台勾选真实手环并明确启动，每次最多 30 分钟，重复启动不续期。通知栏有停止入口，移除任务、停止或到期均取消本次状态。
- 一次只运行一种后台模式。旧“后台 BLE 传输”继续仅传输；新模式不接受手机测试按钮、通知栏批准动作或外部广播批准。
- 启动时捕获已导入的 VM 配对资料和所选手环。切换资料、手环或普通桥接状态会使本轮失效；停止、过期或新请求替换后，旧回调和排队决定均不能签名。
- 每个新请求先由原 `VmRelayClient` 验证电脑签名、账户挑战及有效期，再使用原 `PromptGate` 限制通知与点击。Wear Engine 已消费票据后只提交一次，不再二次消费，也不自动重发决定。
- 只使用原 VM 实验 Keystore 身份，不读取、保存或发送 Windows 密码。后台模式要求已登记的 BLE 回环地址；证书和原生一次性验签保持不变。
- 部分唤醒锁只覆盖正在进行的 IO，最多 45 秒；没有关闭系统节电策略。OEM 的后台限制仍需实测。Android 官方建议从前台启动 `connectedDevice` 前台服务以[在后台维持 BLE 通信](https://developer.android.com/develop/connectivity/bluetooth/ble/background)。

已交付的决定不能通过停止操作撤回；原生挑战有效期和一次性限制继续生效。`DELIVERED` 仅代表观察到授权交付响应，不能替代实际 Windows 桌面或 WTS 结果。

## 已执行的检查

生产协调器 `VmWearSession` 的 20 项定向检查通过，覆盖：通知发送不等于点击、重复请求与重复回调、确认／拒绝、未消费回调、排队后的停止／过期／换配置／断线／新请求、提交失败不重发、未连接不轮询、晚到结果、单调时钟期限及 SDK 取消。设备、网络和 SDK 事件为模拟；没有调用 Windows 登录。

Android Java 检查合计 103 项通过；Android 0.4.0 构建、签名校验及 Lint 通过，0 错误、4 警告。Windows 和原生 Provider 未修改，不重复继承为新后台模式实机通过。

## 下一次只需这一轮实测

1. 手机保留数据更新至本地 `artifacts/BandKey-bridge-0.4.0-debug.apk`。保持原手环配对和 VM 实验密钥，VM 中继与登录组件无需重装。
2. 使用准备好的新版 Windows BLE 助手。在手机 VM 实验页勾选真实手环，直接点“启动后台手环确认”，确认本次 30 分钟范围；不要同时开启旧的后台传输模式。
3. 手机回到主屏幕并锁屏。由用户仅锁定 VM，在真实手环确认新请求，观察是否实际返回桌面；不能把手机响应或通知发送当成成功。
4. 再锁 VM，先等 8 秒不操作，再点手环拒绝，应始终锁屏。随后从手机导出“后台手环确认记录”，核对本轮拒绝响应是否实际被观察到。
5. 从通知栏停止本次模式，再锁 VM，应继续锁屏，旧通知不能复用。结束测试后停止电脑助手。

新 JSON 记录只包含状态、计数和停止原因，不含密钥、密码、账户 SID、nonce、手机地址或手环标识；始终标记未独立验证 Windows 解锁。

## 回退

手机点“停止轮询并取消待确认请求”或“停止全部 BLE 传输”，均会停止新后台确认；通知栏也可停止。之后可使用原页面前台测试方式。必要时直接强制停止 BandKey；VM 原系统登录方式保留。本阶段没有安装或修改主机／VM 的 Credential Provider。
