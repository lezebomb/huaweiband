# BandKey Windows 便携开发版

运行本目录 `BandKey.exe`，无需另装 .NET。Windows 11 x64，支持 BLE 的适配器。

当前功能：被动 BLE 扫描、滤波/滞回/延迟判断、离开后调用 Windows 正规锁屏接口、设备授权管理、签名 HTTPS 手机桥接。首次默认关闭自动锁屏和网络监听。

**普通托盘代理当前不提供 Windows 解锁。** 独立 VM 已有真实手环确认、本地／微软账户返回桌面及拒绝保持锁屏的用户确认；长期 BLE／后台稳定性、微软账户卸载恢复和宿主机 LogonUI 尚待验收。普通代理验证授权后仍需原有 PIN/密码。

1. 打开后先核对手环广播地址，关闭自动锁屏观察近/远状态并校准。
2. 确认广播稳定后，手动开启自动锁屏。默认信号消失只显示 Unknown，以避免设备静默导致误锁。
3. 手机桥接需要单独的 BandKey Android APK、华为 Wear Engine 服务授权与应用配置，并互相导入、核对公钥指纹。普通网络 HTTPS 需要可达网络；手机 BLE 通道不要求同一 Wi-Fi。
4. `runtime/` 保存此用户的 DPAPI 应用私钥、配置、公钥与日志，不可随便携包分发；本交付包不含该目录。
5. 关闭窗口缩至托盘；托盘“退出”停止程序。卸载前退出，删除该文件夹。若另外配置了登录后启动，应先取消对应任务。

没有安装或注册 Credential Provider、修改 Windows 登录配置、保存 Windows 密码或 PIN。首次登录前不提供手环登录。

完整技术状态、协议、硬件步骤与登录集成限制见 `docs/`。源工程提供构建、测试和当前用户登录后启动脚本，开发版源码位于原项目目录。

手机实验另有不依赖同一 Wi-Fi 的 USB 开发通道，见 `docs/usb-transport-test.md`。真机 USB / Keystore / HTTPS / CNG 验签已通过合成账户测试；随后实际 VM 的一次确认解锁及未确认／拒绝保持锁屏获用户确认。普通代理的认证后端不因传输通道变化而启用。

新增 `BandKey.exe --ble-bridge` 和托盘“手机 BLE 通信实验”，见 `docs/ble-phone-transport.md`。Mate60 合成账户检查为 USB 七轮 36 项、BLE 11 项及两路 CNG 各 2/2，BLE 两端计数一致。随后实际 VM 的 BLE 正例和未确认／拒绝反例也获用户确认，未建立 USB 数据映射，无需同一 Wi-Fi。最后拒绝后出现一次流错误，持续连接稳定性尚未通过；没有拔线或长期后台验收。完整范围见 `docs/mate60-validation-20261019.md`。

另有显式 `--vm-bridge` 手机确认实验入口，仅支持已登记手机公钥的 VMware/build 26300 来宾；在物理机拒绝运行，不自动安装或注册。须使用独立 VM Phone Lab 镜像中的原生安装器，并按 `docs/vm-phone-bridge-test.md` 操作。实际返回桌面的结果由用户确认，工具仅观察到手机请求与交付，未独立采集该轮 WTS 归因。它不改变普通代理的认证状态，宿主机 MSA/Hello 和完整恢复仍待验收。

只读诊断：`BandKey.exe --probe --seconds 30 --output <绝对路径.json>`；这不会锁屏、配对或写入手环。

Windows BLE 助手对连续可恢复故障最多重连三次，等待 11／12／14 秒后使用新通道。当前连接完成至少 3 条流、且完成时间跨度达到 60 秒后，才可恢复重试额度；错误帧／权限拒绝仍停止，运行期限不延长。历史最多保留 32 条，累计故障数单独保留，见 `docs/ble-recovery-budget-20261027.md`。

每次原生请求仍独立检查有效期与一次性消费，不自动重发授权。`passed=true` 只说明助手按要求结束，还要检查失败记录；真实连续轮询仍出现过 TCP 中止，不能称为长期稳定通过。手机保留原0.8.0；本轮不用重装 APK 或 VM Provider。0.9 中继候选及 0.8.2 Android 候选仍待硬件验证，见 `docs/fixed-phone-native-recovery-0.9.md`。
