# 2026-10-27：完整返回与 VM 卸载恢复

本阶段沿用一加原版 0.8.0、真实 Band 11 Pro、VM 0.9 中继和 Windows 0.9.1 BLE 助手；没有更新 APK、原生 Provider 或手环配对。全部 VM 键鼠由用户操作。

## 固定手机完整场景

用户在 VM 勾选持续断连后自动锁屏，接近等待 1 秒，保持桌面，没有手动锁屏。手机留在电脑旁，只佩戴手环走到已有断连位置，停留后返回。用户确认：VM 已自动锁屏，返回收到新编号通知并确认后自动回桌面，没有输入 Windows 密码。返回通知估计约 10 秒，不能与原地锁屏约 3 秒视作相同测量条件。

手机记录 114 次 SDK 查询全部成功：103 次连接、11 次断连，未知／错误为 0。96 次固定手机响应包含 86 次连接、10 次断连；发生 1 次 NEW 刷新、1 次附带 WIN 挑战、1 次通知和1次批准响应。批准调用 1337 毫秒。原生请求可能已在离开期间过期，返回仍须刷新并确认，不能为了提速复用旧批准。

只读 UI 采样观察到两次断连状态，随后进入提交状态及重新连接状态。采样约 13 秒一次，不能据此精确拆分“身体返回 → 手环重连 → SDK确认 → 原生刷新 → 通知显示”的每段耗时。现有中继已在 NEW 响应中最多等待 400 毫秒以附带新挑战，本阶段没有重复添加该机制、加长超时或恢复失败过的 1 秒正常上报试验。

Windows 记录 1 次连接、13 条完整流、MTU 517／Indication，故障 0，发往手机45981字节、来自手机118463字节。按停止文件正常收尾。手机报告在停止助手后导出，因此其断连计数1、HTTP102次请求／100次完成含收尾阶段，不能当作稳定传输期间额外出现两次自然失败。手机开始流与 Windows 完成流也不是同一计数。

## 卸载与恢复

1. 用户停止并关闭中继，在 VMware 保存“04-BandKey-0.9-working”快照。
2. 使用既有 MSA VM ISO 中的安装器执行 Remove。用户报告弹窗明确为“Lab registration and files removed”，没有报告残留。
3. 用户重启 BandKey-Win11，以同一个 Windows 用户的原系统登录方式正常进入桌面；没有运行 BandKey。
4. 用户还原刚保存的快照，原 0.9 中继自动读取当前账户登记公钥并正常启动。
5. 开发端重新接通手机 BLE。恢复后的 VM TLS 指纹与此前公开配对匹配；用户再次锁定 VM，在真实手环确认后自动回桌面，未输入密码或切换登录方式。

恢复后一轮手机记录1次新通知、1次批准、NEW刷新0；81次SDK查询全部连接成功、错误0，73次固定手机响应。批准调用2064毫秒，HTTP76次请求／75次完成是在服务仍运行时采集，不能只用差值判断失败。Windows记录1次连接、9条完整流、故障0，发往手机34234字节、来自手机88055字节。

移除程序和原生DLL均使用已校验的既有镜像，SHA-256分别为 `699c6aa6b8f5653c0f3f337cfc8bddff8eab702e1260715f1324ae1d6bfbfb94`、`9f60ae7222f0836f9a4739370f4676e2460def592a4fd53924a0e18943b70ced`。没有执行宿主机注册、清理系统Provider或操作Ubuntu。

## 证据范围

自动锁屏、原登录可用、移除完成、快照恢复和实际桌面结果来自用户观察。手机工具记录签名响应；本轮未独立读取来宾注册表／账户类型，也未独立采集 ReportResult 或 WTS 归因。原始JSON、UI记录和公开配对均保存在忽略的本机 artifacts/hardware-20261027/，不上传。

本阶段的两轮传输均未记录故障，但不抹除[此前恢复测试](hardware-validation-20261027.md)的3次故障，也不构成长时间稳定性验收。VM快照恢复不能代替物理主机的安装与回滚方案。正式主机安装器／登录后端接入和主机验收仍未完成，实验组件的VM限制保持不变。

测试结束后手机测试服务和两轮Windows助手均已停止，VM保留恢复后的已登记状态及原系统登录方式。以后需要再测试时启动中继和手机服务即可，不需要重复安装。
