# 两种接近模式：后端状态与接入约束

用户于2026-10-25确认两种使用场景都需要，且都保持“靠近后手环点一次确认”，不会改成无点击自动解锁。

| 模式 | 手机位置 | 接近来源 | 适用场景 |
|---|---|---|---|
| 固定手机 | 与电脑放在一起 | 选定手环与手机的连接／断连状态 | 只戴手环离开、洗澡、回来 |
| 随身手机 | 跟随用户 | 已绑定手机与电脑的 BLE RSSI | 手机和手环一起出门、回来 |

固定手机模式仅说明手环进入手机的蓝牙连接范围，不表示精确到桌前。如果离开的地方仍能保持连接，就没有离开／返回事件。随身手机模式不能用于手机留在桌面的情形；程序不会静默自动切换模式。两者都仍须通过真实手环当前点击及 Windows 认证。

## 已实现的后端

在原 AutoLockController 中新增显式输入选择，保留原有直接手环广播接口的兼容性：

- SelectInputMode(FixedPhoneBandConnection) + ObserveBandConnection：接收经过认证且未过期的选定手环连接状态。
- SelectInputMode(CarriedPhoneRssi) + ObserveCarriedPhone：复用已有中值滤波、平滑、滞回、接近／远离时间窗口。
- 固定模式不伪造RSSI，不接受手机RSSI作为手环状态；错误来源直接拒绝。
- 短暂断连不触发锁屏；先观察稳定连接才进入离开锁屏就绪状态。持续断连只发出一次锁屏请求，Session 0不调用交互锁屏。
- 手机心跳丢失、状态未知、蓝牙／来源不可用会取消就绪，不当成手环走远。恢复后需要新的稳定连接。
- 切换模式、手动解锁或会话变化重置旧状态。CanRequestConfirmation只表示当前锁屏并处于接近状态，不批准、不签名、不宣称 Windows 已解锁。

新增12项定向模拟检查，核心合计128/128通过。没有使用主机真实锁屏，也不将模拟连接轨迹算作手环走远／回来验收。

## 固定手机流程已接入候选，等待 VM 实测

Android0.5.0查询所选手环状态，签名绑定当前PC运行、手机、手环哈希、采样时间和递增序号。VM中继接收状态、判断接近／断连，并默认关闭自动锁屏；勾选后只锁该VM交互会话。

返回时使用独立NEW签名生成新的原生随机挑战，能够处理电脑已锁屏超过30秒的情形；刷新不读Vault、不批准解锁。真实手环点击仍须签署新WIN用途授权。代码已通过核心142项、Windows83项和原生221项检查；Java/C#/CNG专用刷新签名互通通过。后两者的认证上下文为合成输入，不是实机成功。

更新步骤、预期结果和回滚见[固定手机VM教程](fixed-phone-vm-20261025.md)，消息边界见[协议](fixed-phone-protocol.md)。现有VM需要用户手动更新登录组件至协议v3；本阶段没有替用户操作VM，也没有注册主机登录组件。

尚待完成：

1. 本候选真实VM长时间锁屏→手环离开／返回→新请求→确认／拒绝，以及持续断连自动锁屏。
2. 随身手机RSSI模式尚未接到BLE链路、中继和设置。输入必须来自已绑定手机，不能按邻居广播或最强信号判断。
3. 微软账户真实VM认证及主机恢复／卸载验收，然后再评估正式主机部署。

手机与VM中继均需显式开启固定模式，不能只改一端。停止、换模式或睡眠恢复撤销旧运行状态；未知／心跳丢失不当作手环离开。不继承旧授权。

## 本轮真实手环走远／返回

用户将手机留在电脑旁，只戴手环走远并返回。复用已安装0.4.0的官方SDK诊断，约90秒内采得12个状态：起初3个已连接，随后6个断开，最后3个重新连接，查询均无错误。首次断开样本约28.6秒，首次重新连接样本约76.7秒，不能将样本时间当作精确的断开／重连延迟。

这是固定手机方案的真实状态来源验证，不是自动锁屏、返回后生成新请求或 Windows 解锁的验收。没有用手机RSSI替代手环连接状态，没有重配、重置或安装新APK。原始状态样本位于本地忽略的 artifacts/validation-20261025/anchor-walk-observation.json。

共享控制器的Release构建0警告0错误，核心128/128、Windows集成81/81通过。新增12项使用模拟状态验证策略，真实走远样本独立记录，不合并成自动执行功能已通过。
