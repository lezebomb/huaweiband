# 0.9 中继候选：新锁屏请求直达与重建恢复

本轮以已经实测的 0.8 为回退基线。0.9 用户态中继已在 VM 完成真实手环批准、等待／拒绝、BLE恢复后批准及完整离开／返回；原地通知、确认后解锁各约3秒，返回通知约10秒。VM卸载、原系统登录和快照恢复后再次解锁也已获用户确认。长期稳定性及主机部署尚待验收。手机保留原签名0.8.0，无需重新配对手环或重新登记Windows密码。详见[原地实测](hardware-validation-20261027.md)、[完整返回与恢复](vm-return-and-recovery-20261027.md)。

## 为什么修复

微软账户 VM 已在原 0.8 组合下完成真实手环确认解锁，以及等待 8 秒后拒绝仍保持锁屏。首次失败的原生日志只有请求创建、等待和过期，没有提交 Windows 认证；不能将其称作微软密码不兼容。桌面结果来自用户观察，不是工具独立采集的 Windows 认证成功事件。

尝试把手机正常上报由 3 秒改成 1 秒的 0.8.1 后，用户反馈几十秒没有新通知。报告显示 `native-replaced`、没有提示和决定，同时 BLE 流多次超时。该试验没有证明提速有效，已保留数据恢复到原版 0.8.0；不把它作为可用版本。HTTP 错误码当时没有导出，不能猜测是服务器限流。

软件复现发现一条竞态：中继提交用途为 NEW 的刷新证明后，先读到初始 WIN 请求并固定它，原生 Provider 随后处理刷新、创建另一个 WIN 请求，中继就持续拒绝替换。1 秒轮询可能更容易遇到这个窗口，但尚不能据此解释全部 BLE 超时。

## 这次改动

- 刚从明确解锁转为锁屏，且此前接近证据仍新鲜时，直接使用锁屏后生成、绑定当前账户 SID／会话的新 WIN 请求，省去冗余 NEW 往返。缺少有效请求只短等最多 1 秒，再退回原刷新流程；已经锁屏、旧请求或旧接近证据不能走此捷径。
- 已固定的原生请求被替换时，立即拒绝旧请求，包括后来重新出现的旧文件；后续有效状态报告可发起全新的 NEW 证明。每次锁屏／返回最多恢复两次，避免无限刷新。恢复不会自动批准，真实手环仍须确认新的 WIN 请求。
- 读取原生公开交换文件时允许系统删除文件，避免短暂读取占用阻碍原生取消。不会覆盖已有批准或刷新证明。
- Android 候选 0.8.2 恢复正常 3 秒上报，连接故障退避、BLE 重连时清理旧 HTTPS 连接，并增加 HTTP 状态码、失败类型及决定阶段诊断。候选已构建、签名验证通过，未安装；手机仍是已验证的 0.8.0。

Native DLL、登录安装器、密文保存方式、30 秒授权期限和签名格式均未更改。0.9 中继与原 0.8 手机协议兼容，可以先只换中继。

## VM 手动更新与回滚

目前无需执行，等方便观察手环时再做。VM 内操作仍全部由用户完成。

1. 保存 VM 快照，停止并关闭旧中继，备份完整 VmBridge 目录。将 VMware 光驱切换到本轮 `BandKey-Relay-Patch-*.iso`；实际路径及 SHA-256 记录在本机 `artifacts/latest-relay-patch.json`。
2. 将光盘 Patch 内全部 5 个文件一起覆盖到现有完整 VmBridge 目录。不要从空目录运行，也不要运行登录安装器。原目录的运行时、公开配对、登录登记保持使用。
3. 运行原 Start-VM-Bridge.cmd；启动文字应显示“0.9 新锁屏请求直达，重建恢复”。监听仍为 VM 实际私网 IPv4，手机访问地址仍为 https://127.0.0.1:19443，固定手机、接近等待 1 秒；首次先关闭自动锁屏，保持桌面，由开发端接 BLE。

之后只需要一轮原地锁屏确认、再一轮等待／拒绝检查；同时记录通知延迟和确认后延迟。新请求失败时先导出会话记录，不必反复走远或重装。

回滚：停止并关闭 0.9，把备份目录的 5 个文件一起复制回去，启动原 0.8 中继。手机原版无需变化。如果需要回退整个 VM，使用更新前快照，并核对相应公开配对身份。保留系统密码／Hello 登录方式。

## 验证与仍待完成

核心 176/176、Windows 93/93、Android Java 110/110 通过；Windows Release／自包含发布无警告或错误，Android 候选构建及原签名校验通过。新增检查覆盖新锁屏直达、错误账户／会话、旧请求、过期接近、原生替换不复活旧请求、两次恢复上限，以及实际回环 TLS／文件交换中的新签名授权和旧决定拒绝。集成测试用合成原生文件，没有调用系统登录。

本轮只读 RSSI 诊断在手机 BLE 连接期间收集 231 条当前 GATT 对端广播，范围 -38～-30 dBm，最大间隔约 19.9 秒，跨两个连接代次。只按当前地址／地址类型匹配，未以协议认证身份，未用于距离控制。不能据此开放手机随身模式，更不能当成手环广播；其余绑定后端见[携带手机模式](carried-phone-backend-20261026.md)。
