# 常驻进程存活但通信停止：2026-10-29

用户反馈“电脑好像没有常驻，一会功能就不行”。检查时电脑进程和登录任务一直存在、未暂停，但自有状态报告停在13:25，至22:11已停更近9小时，最后记录蓝牙订阅错误。仅凭进程存在宣称常驻正常是不充分的。

手机当前前台常驻服务仍运行、自启动配置启用，电池白名单和后台权限仍在；系统退出记录却显示当天多次`OTHER KILLS BY SYSTEM`。这些是系统清理，不能宣称应用已完全避免厂商后台回收。

## 修复

- 先请求旧电脑代理正常退出；12秒内未完成，只结束核对过路径的BandKey进程，再由原启动任务恢复。之后实时报告、手机签名状态及BLE恢复。
- 电脑蓝牙连接／流处理在后台任务执行；状态快照读取缓存MTU，不在界面线程同步访问WinRT蓝牙对象。该访问存在拖住状态报告的风险，但没有取得停顿堆栈，不能宣称已证明是本次唯一根因。
- 中继停止等待最多15秒。若旧蓝牙任务仍不结束，撤销中继授权后以失败状态退出本应用，交由监护重新启动，不在同一进程内叠加新旧蓝牙连接。
- 登录任务运行独立、非管理员的本用户监护脚本，守护现有代理。状态报告停止更新90秒时仅重启本应用，不把“手机暂时离开”当作卡死，不锁定或解锁Windows。
- 主动暂停、正常退出及更新／卸载停止标记会被尊重；旧任务和新监护任务的所有者及执行路径均检查。卸载器同时支持原直接启动和新的监护启动方式。
- 手机未重装，设备密钥、两分钟原生组件、原密码／Hello、关闭自动锁屏的设置保持。
