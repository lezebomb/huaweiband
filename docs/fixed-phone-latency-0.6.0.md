# 固定手机延迟优化：0.6.0

0.5.2已由用户观察到自动锁屏、通知和确认后的数秒等待，体验不佳。优化前直接锁屏约15秒通知／5秒解锁；0.6.0实测用户报告约10秒通知／2秒解锁，仍未达到理想通知速度。

本阶段只改手机固定模式：

- 同一签名VM会话复用证书固定的HTTPS连接，固定Host验证器和SSLContext，完整消费有界响应。每20秒通过Connection: close主动结束，保持低于BLE原45秒及128KiB字节流上限。失败或停止关闭连接，不放宽证书、跳转和身份校验。
- 收到刷新响应后短时加快原生就绪探测，避免固定等下一轮3秒心跳。
- 等待真实点击时不重复轮询同一原生挑战；已排队的决定优先执行。主循环为500毫秒调度，正常状态报告仍限3秒一次，不增加反复通知或重试已消费决定。
- 报告新增HTTP请求数／耗时／退役计数、决定排队及签名通信耗时，不含载荷、地址、nonce、密钥或凭据。

四项定向协调器回归通过，生产JDK合计110项；Android构建、签名和Lint通过。Windows及原生未改，不重复跑无关测试。物理主机没有注册登录组件。

## 实机结果

首次基线14次HTTPS完成使用2条手机BLE TCP流，正常退役1次。随后真实确认报告143次HTTP尝试／142次完成（采样时1次进行中）、20条手机TCP流、19次退役，无蓝牙断连。状态138次、刷新／通知／批准响应各1次。SDK219次查询均连接，无错误，最长56毫秒。确认排队3毫秒，签名加决定HTTP调用1215毫秒；它不含物理按钮到SDK回调及Windows桌面显示时间，不能当作精确的完整解锁耗时。

用户观察约10秒通知、确认后约2秒回桌面。窗口结果来自用户，工具没有独立采集WTS。完整返回在0.5.2已有用户功能反馈，但体验仍需改善。下一步减少刷新、探测、取挑战之间的网络往返。

## 操作与回退

手机保留数据更新一次到0.6.0，PC继续原0.5.1中继，不改登录组件。要重新测试只需原地锁VM，收到当前编号通知后确认，不必重复走远。

停止从手机后台服务或通知栏执行，连接及广播随服务结束。必要时可保留数据恢复此前同签名调试APK；不得卸载／清数据。原系统登录方式仍保留。
