# VM 中继会话记录更新

此更新只替换普通用户态 VM 中继程序，不更新或重装 Credential Provider，不改变已登记的手机公钥、VM 密码或系统登录选项。真实来宾操作仍由用户完成。

## 新行为

- 中继窗口自动注册当前会话的 WTS 锁屏／解锁通知，并每秒查询会话状态。启动时已经处于桌面不算一次解锁。
- 复用原有会话实验工具的记录逻辑：通知和查询分开计数，延迟查询不能覆盖通知而产生虚假解锁；未知状态中断查询链，最多512条变化记录。
- 最近一轮中继分别记录新请求数、决策数、授权文件交付数、签名拒绝和无效／失败数。重复轮询不增加新请求数；交付成功不变成 Windows 解锁成功。
- 每5秒及会话变化时保存报告，关闭时补存；可点击“导出本次会话记录”。报告无用户名、SID、手机／电脑公钥、请求、签名、密码和 PIN。
- 睡眠恢复时撤销并停止当前中继，需手动重新启动。撤销阻止后续中继提交，**不能撤回在此前已经交付给原生组件的文件**；原生验签、有效期和会话边界仍独立执行。

报告位于 VM 的 `%LOCALAPPDATA%\BandKeyVmBridge\reports\relay-*.json`。`session` 是本次窗口生命周期的会话观察，`latestRelayActivity` 只代表最近一次启动的中继，不能把两者数量一一对应。`unlockAttributedToBandKey` 保持 `false`：WTS 确认桌面变化本身不能证明是哪一种凭据导致。

## 最短使用步骤（手机回连后）

1. 回到 VM 桌面，停止并关闭旧的“VM 手机通信实验”窗口，保留原有 Provider。保存当前 VMware 快照。
2. 将新中继更新 ISO 挂到 VM 光驱，把 `VmBridge` **整个文件夹**复制到 VM 本地的新目录；双击其中 `Start-VM-Bridge.cmd`。不要从新旧目录混用 DLL，也不要运行任何旧安装器。
3. 导入之前已经登记的一加 `.bandkeypub`，监听地址填 VM 实际 IPv4（此前为 `192.168.71.130`），手机访问地址保持 `https://127.0.0.1:19443`，启动中继。电脑身份仍从原来的用户数据目录加载，不会生成新的配对身份。
4. 手机安装0.4.0准备版后，显式开启后台手环确认；确认一轮、等待／拒绝一轮即可。按[后台实测说明](vm-background-wear-20261023.md)进行，不必重复全部历史用例。
5. 回桌面后看中继的交付／拒绝计数和 WTS 观察，导出报告。若出现实际异常，再按报告定位；不以“授权已交付”代替桌面结果。

回滚：关闭新中继，恢复运行原来目录中的中继。它们使用相同的既有身份目录；此更新没有注册项、后台任务或系统组件需要卸载。手机可停止新后台会话，回到原来的前台模式，无需重新配对手环。

## 当前验证边界

Release 构建0警告0错误，核心116/116、Windows集成81/81通过。其中会话状态为模拟输入，真实 HTTPS、签名和文件交换仍走生产代码；新增 I/O 故障检查确认失败授权不重试。修正了集成测试代理停止时的监听器释放竞态（只在已取消时忽略 `ObjectDisposedException`），未将其当作物理 BLE 修复。

更新尚未在来宾运行，WTS 实际自动报告和睡眠恢复需用户操作 VM 验收。此前真实手环解锁观察来自旧中继，不能沿用为本次更新实测通过。
