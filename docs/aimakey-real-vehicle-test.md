# 之后接触实车时怎么测试

当前已交付 `AimaKey-0.1.0-mock.apk`，手机安装名为“AimaKey 模拟实验室”。它的启动／关闭只改变模拟状态，**现在不能控制真实车辆，也还没有可安装到 Band 11 Pro 的独立页面**。这次实车测试的目的，是确认官方 App 的正常启动／关闭流程、连接条件和结果反馈，为后续合法接口接入提供证据。

## 不带电脑也可以先做的观察

1. 确认车辆静止、安全停放。使用你已经绑定车辆的**爱玛出行官方 App**，确认显示蓝牙连接。记录当前 App 版本和车辆初始状态即可，不需要提供车辆标识或密钥。
2. 由你本人在官方 App 执行一次“右滑启动”。记录滑动前后控件的文字／图标变化、App 提示、车辆实际电源状态及大致时间。把“App 提示成功”和“车辆确实启动”分别记下。
3. 查看启动后的正常关闭入口：是原滑块变了状态，还是出现单独按钮？用你熟悉的官方正常关闭操作停机，记录 App 提示与车辆实际响应。若 App 没有明确关闭入口，记录这一点，不尝试猜测指令；按你原有的正常方式结束车辆使用。
4. 可单独做一次**不启停车辆**的锁屏连接观察：手机保持蓝牙开启，锁屏约1分钟，再解锁查看官方 App 连接是否维持／恢复。它只能说明官方 App 的连接表现，不能证明 AimaKey 已能锁屏控车。

之后把这些简短结果带回本项目：启动前后控件变化、正常关闭入口和条件、两次动作的 App 提示与真实响应、锁屏后的连接情况。截图／录屏如果包含个人或车辆资料，先留本机，不上传公开仓库。

## 有电脑和 USB 时采集本地只读日志

先正常连接手机并允许 USB 调试，手动打开官方 App。脚本不负责打开 App，也不会点击任何控件。

```powershell
Set-Location D:\huawei
adb devices -l
```

把已授权手机的序列号填入下方命令。车辆安全停稳且你本人准备手动操作时再运行：

```powershell
.\scripts\observe-aima-app.ps1 -Serial '<手机序列号>' -Seconds 45
```

看到 `READY` 后，在45秒窗口内由你本人手动做前面的官方启动、观察和正常关闭。时间不够时分为两次采集，不为赶窗口省略观察。

预期结果：脚本打印 `Local private output: ...`，新目录在 `D:\huawei\.research\aimakey\observations\`。其中：

- `capture.json` 记录采集开始／结束时间和只读范围。
- `logcat.txt` 是指定官方 App 进程的日志。
- `adb-error.txt` 记录 ADB 问题。

输出目录只授权当前 Windows 用户与 SYSTEM，且被 Git 忽略。日志可能缺少关键事件，空日志／无报错都不等于车辆操作成功；保留你的 UI 与车辆实际观察。不要把原始日志、认证材料或 APK 上传到第三方分析网站／公开仓库。

该脚本在本阶段只做了语法检查，**尚未运行实车观察**。若提示找不到官方 App 进程，先手动打开官方 App；若手机断连，重新授权 USB 后再采集。不要 root、清数据、解绑或重装官方 App 来排查。

## 目前能验证和仍不能验证的范围

可以验证：你这辆车在官方 App 中的启动／关闭 UI、正常动作、结果提示、蓝牙连接和锁屏恢复表现。

仍不能验证：AimaKey 的真实启停、Band 11 Pro 双按钮入口、真实 Wear Engine P2P、长期锁屏后台控车。要到这一步，必须先解决[手环入口](aimakey-wearengine-research-20261108.md)与[爱玛合法调用接口](aimakey-aima-analysis-20261108.md)两个问题，再替换 Mock 并安排新的实车验证。

停止本次日志采集不会停止或修改官方 App。AimaKey 不想继续保留时，先在模拟 App 点击“停止后台模拟”，再通过系统卸载“AimaKey 模拟实验室”；原 BandKey、爱玛出行、运动健康和车辆绑定均不需要动。完整构建、软件验证与卸载命令见[开发交付说明](aimakey-development-20261108.md)。
