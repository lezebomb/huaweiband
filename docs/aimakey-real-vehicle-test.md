# AimaKey：用真实手环测试，手机离线保存结果

2026-11-09更新。官方App的“未启动右滑／启动后同一图标点按关闭／锁屏维持连接”已由用户说明，**不再要求到车旁重复演示或带电脑采日志**。最终验收须从手环发起真实车辆操作；本版尚缺常驻入口与真实爱玛适配器，先验证真实手环点击和锁屏手机通信，车辆指令始终为0条。

## 现在就能做：真实手环 → 锁屏手机 → 收件反馈

无需车辆或电脑在旁，只需手机、手环、运动健康保持原连接。

1. 在BandKey主界面打开“AimaKey手环通信诊断（不控车）”；或在AimaKey 0.2.0点“打开BandKey手环真实点击诊断”。
2. 如果Windows手机桥接正在运行，点“打开原Windows手机桥接设置”，点“停止轮询并取消待确认请求”；如有独立BLE传输，再点“停止全部BLE传输”。返回诊断页。程序不自动暂停它们。
3. 点“发送一次手环诊断，再锁屏放入口袋”。看到SDK已接受后锁屏，手机可以一直放进口袋。
4. 在手环查看标题为“AimaKey·仅点击诊断”的通知，120秒内点击“启动测试”或“关闭测试”。不要与电脑解锁通知混淆。
5. 预期随后出现“手机已收到／未控制车辆”的无按钮回执。没有看到回执时，不能只凭已发送就认定点击到达；稍后看手机记录。
6. 回到手机点“查看／导出本机记录”，查看WRIST_GESTURE、对应START／STOP和点击时锁屏标志；点“导出诊断ZIP”选择手机保存位置，回家再分析。
7. 完成后在原Windows手机桥接设置点“启用手环确认（主机常驻／VM 30分钟）”，恢复原本使用的后台模式；原配对资料仍在。

一条诊断只接受一个动作，测另一个按钮需要回到手机手动开始第二次。没有通知、断连、过期或结果不明时，不自动续发或转成车辆动作。离开页面不取消已明确开启的120秒窗口；通知栏和页面都有取消入口。应用被系统杀死后不重放旧操作。

这只是获用户同意的临时通知诊断，不是最终常驻页面。记录保存本应用事件，不是官方爱玛App的完整日志，也不能作为命令导回执行。

## 独立手机模拟模块

“AimaKey模拟实验室”0.2.0继续测试模拟启停、超时和停止门控，并自动持久记录、支持ZIP导出。手机按钮产生PHONE_GESTURE，不冒充WRIST_GESTURE。vehicleSimulation=true表示车辆仍模拟，与手环点击是否真实是两个维度。

## 以后到车旁的真正验收

真实控制接口接入、手环入口就绪后，车辆安全静止时，手机先开启诊断后锁屏放入口袋：

1. 从手环明确发起“启动”，核对车辆实际启动和手环最终确认。
2. 车辆保持安全静止，从手环明确发起“关闭”，核对车辆实际关闭和手环最终确认。
3. 手机记录连接、请求发送、车辆接收、车辆状态确认或失败；回家再导出，不带电脑。

以上是后续验收标准，**不是当前版本已有的实车功能**。电源状态未知时不盲点官方切换控件；关闭仍须静止和确认；重复启动不能切换成关闭。现在不需要用户再操作官方App来证明已有界面行为。

## 回滚

需要退回BandKey 0.9.5时，可在家中连接USB，使用本机准备的同签名回滚包（不卸载、不清数据）：

```powershell
adb -s <手机序列号> install -r -d D:\huawei\artifacts\aimakey-field\BandKey-rollback-0.9.5.apk
```

ColorOS若要求安装确认，由用户正常允许。回滚后检查并恢复原后台确认模式。独立“AimaKey模拟实验室”可单独卸载，无需卸载运动健康、HMS或爱玛出行，不改变手环／车辆绑定。

架构和证据边界见[本轮说明](aimakey-field-architecture-20261109.md)。
